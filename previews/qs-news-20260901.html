In one test, my AI research workflow held a report back. It found that some source material had been collected badly, the wording sounded too certain, and the evidence was too thin to support the final answer. The model was the same one I already use. The difference was the written job, the reference files and the person checking the answer.

The setup beats the model

That result came from three ordinary pieces. By setup, I mean the written instructions, the reference files and the person who checks the answer. The model is only the part that turns those things into words.

Write down the job

First, I wrote down the job in plain language. The instructions say which question the workflow is answering, which files it may use, what counts as evidence, and what to do when sources disagree or leave a gap. That stops each new chat from quietly inventing its own rules. It also gives me something to inspect when the work changes.

Give it the right files

Next, I kept the question, the conversation that clarified it and the source material together. The workflow links each statement in the report to the material behind it. Then it runs simple checks I wrote in advance. They look for missing sources, unsupported numbers and language that sounds more certain than the evidence. When the source material was collected badly, the workflow tried one limited repair. When that did not produce enough support, it held the report back. It did not quietly lower the standard to make the report look complete.

Leave one decision to a person

A person still decides whether the evidence is good enough to use, and whether the question has been answered properly. The system can point to a weak source or a doubtful sentence, but it cannot know the business cost of acting on a wrong answer. The reviewer can ask for more work or leave the report unused.

Try it on one real research question this week, such as checking a market, supplier or customer issue. In a fresh chat with the model you already use, write the question, list the files it may use, and name the one check a person must make before anyone acts. That is enough to see whether the process improves the answer before you pay for a heavier model. Read the answer against the source files before you use it.

From my desk

A system that catches up when I return

I built another system that checks itself when I return to work. If it missed a weekly check or daily update, it catches up then. I don’t need to remember a timer or press a button. The model helps, but the instructions around it make the result dependable.
